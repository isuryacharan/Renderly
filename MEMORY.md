## Decisions

| Date | Decision |
|---|---|
| 2026-11-24 | Renderly 2.0 is a browser-only rewrite in TypeScript. It does not carry over the earlier codebase or its copyleft licence. |
| 2026-11-24 | Browsers: Chromium-first. Chrome and Edge get every feature; Safari and Firefox are best-effort with fallbacks. |
| 2026-11-24 | Store: git registry plus CDN first. Formats must allow a hosted service (accounts, ratings) later without breaking packs. |
| 2026-11-24 | Packs: two tiers. Declarative (JSON, GLSL, assets) and sandboxed scripted packs with stricter review. |
| 2026-11-24 | Licence: Apache-2.0, chosen over MIT for its explicit patent grant and trademark clause. Contributions are signed off with the DCO, not a CLA. |
| 2026-11-24 | Fonts: the Google Fonts catalogue for text and captions. Fonts used by a project are stored with the project. |
| 2026-11-24 | Stack: mediabunny + WebCodecs, WebGL2 via three.js, GLSL ES 3.00 for packs, Web Audio with an AudioWorklet clock, File System Access + OPFS, React for panels and canvas for per-frame surfaces. |
| 2026-11-24 | Time is stored as integer flicks (1/705,600,000 s). |
| 2026-11-24 | The store is free. No paid items for now. |
| 2026-11-24 | No other video editors are named anywhere in the repository. |
| 2026-11-24 | `SPEC.md` and `docs/plans/` are git-ignored and kept locally. |
| 2026-11-24 | Toolchain: Node 22+, pnpm 10 workspaces, TypeScript 6.0 (7.0 waits for typescript-eslint support), Vite, Vitest, ESLint, Prettier. Prettier formats code only; Markdown and the preview templates keep their authored layout. |
| 2026-11-24 | Exact seek drives `VideoDecoder` directly and skips H.264 frames with `nal_ref_idc = 0` before the target (about a third of the frames on NVENC test media). Median 4K long-GOP seek went from 145–154 ms (mediabunny `getSample`) to 86 ms with identical pixels. HEVC still uses the full decode. |
| 2026-11-24 | Decode back-pressure is by credit: a worker sends at most N frames (default 6) until the receiver closes some, so a leak stalls decoding instead of filling GPU memory. |
| 2026-11-25 | Render worker playback start: the clock waits until the decoder has filled its frames-in-flight budget and three display refreshes in a row were on time (at most 1 s), and for the first 500 ms a late refresh delays the clock instead of skipping frames. Starting a hardware decoder stalls the GPU for 30-100 ms; without this, 4K starts dropped 1-8 frames. |
| 2026-11-25 | The decode worker is reached through a MessagePort, so the render worker receives frames directly. |
| 2026-11-25 | Audio clock: the AudioWorklet publishes the context frame and session frames consumed after every quantum; the main thread writes `getOutputTimestamp()` into the same SharedArrayBuffer every 100 ms; the render worker computes the session time heard when its next refresh reaches the screen (assumed one refresh ahead) and shows the frame for it. Clips without audio keep the display-refresh clock. |
| 2026-11-25 | Audio and video start together: the worklet holds a session until 100 ms is buffered and the render worker sets the session's go flag after its video pre-roll. Every start and stop is a 5 ms gain ramp. |
| 2026-11-25 | A paused playhead snaps to the start of the frame on screen; resume starts there. |
| 2026-11-25 | Audio output runs at 48 kHz; other source rates are refused until there is a resampler (M2). |
| 2026-11-25 | Edit-list playback: consecutive cuts of continuous footage merge into runs; each run gets a decoder stream (the current run, two ahead, and any run starting within 1.5 s, up to eight). A pool of four decode workers is shared; a decoder is freed as soon as its run is fully decoded. |
| 2026-11-25 | Decoders preparing upcoming cuts submit one frame every 8 ms. Bursts of 4K decode stall Chrome's GPU thread for 12-70 ms and drop frames on screen; paced decoding does not, even three at once. Playback decoding now runs in our own loop (`range-decode.ts`) instead of mediabunny's sample iterator, and skips non-reference H.264 frames before the first wanted frame. |
| 2026-11-25 | The audio clock publishes where the last consumed sample ended, not the latest quantum, so the heard time reaches the end of the audio. A ring the decoder has marked complete running dry is the end, not an underrun. |
| 2026-11-25 | Layers: each cut has a layer and a static transform (position, scale, opacity). Each layer keeps its own render target; the compositor draws layers bottom to top with premultiplied alpha. Sound comes from layer 0 until the audio engine mixes layers (M2). |
| 2026-11-25 | Decoder budget: a pool of six decoders, five for streams and one for keyframe-only updates and seeks. Current runs get decoders first, top layer first; layers left over show their nearest keyframe twice a second. |
| 2026-11-25 | The renderer accounts for its GPU memory (render targets, upload texture, decoded frames on loan) against a 1.5 GB ceiling; targets past it are refused. The browser does not report GPU memory, so this is accounting, not measurement. |
| 2026-11-25 | Scrubbing: one seek in flight per layer, newest request wins; keyframe pictures at reduced size (within 960×540, no mipmaps) while the playhead moves, spaced at least 25 ms apart (up to 40 updates a second); exact frames once it rests 120 ms or the drag ends; a 12-entry cache of exact composites at half size. |
| 2026-11-25 | Accepted by the owner: a 4K drag that starts after the GPU has idled may show UI frames up to ~55 ms for its first ~0.4 s. S0.7 counts as done; proxies (M6) are the later fix. |
| 2026-11-25 | Export runs in its own worker with its own four decoders, composites with the same uploader and compositor as the preview, encodes through mediabunny (VideoEncoder, AAC) and streams the MP4 to a FileSystemWritableFileStream with the index at the end. Audio comes from the bottom layer through the playback decode code, encoded in 1,024-sample chunks. Exact-frame requests in the renderer are serialised. |
| 2026-11-25 | Accepted by the owner: during a 30-minute export the page's renderer process grows ~370–430 MB before levelling off and releases it afterwards, while the main heap and accounted GPU memory stay flat. S0.8 counts as done; S0.9's benchmark should track process memory over long exports. |
| 2026-11-25 | M0 engine decision `docs/decisions/0001-engine.md`: **go**, accepted by the owner. Every measurable §6.4 target passes in `pnpm bench` (headless Edge, RTX 5060). |
| 2026-11-25 | The engine benchmark is `pnpm bench` (Playwright driving installed Edge or Chrome on the GPU); nightly in CI on a self-hosted runner labelled `gpu`. |
| 2026-11-25 | Project schema: Zod 4 (MIT) defines it once; JSON Schema is generated into `docs/schema/` and a test fails when stale. Property tests use fast-check (MIT). Ids are 16 random Crockford base-32 characters. Frame rates are exact `[num, den]` pairs; times past ±2^53 flicks (~147 days) are refused, not rounded. |
| 2026-11-25 | Commands and undo: Immer 11 (MIT) patches, not snapshots. Commands are plain `{ type, payload }` data with Zod payloads; ids of new things travel in the payload so commands are deterministic. The store validates the whole project after each command and refuses one that breaks it. `revision` sits in the document but outside undo. A gesture previews against its starting state and commits one undo step; dispatch is refused while one runs. View state is a separate store. |
| 2026-11-25 | Timeline rules: inputs snap to the nearest sequence frame; trims clamp at the source, neighbours and one frame instead of failing; magnetic tracks are packed from 0 after every edit and new clips go in at the nearest clip boundary; ripple delete closes space per track only; locked tracks refuse clip edits. Clips a command creates without a given id get one derived (FNV-1a) from the original id and the cut time. |
| 2026-11-25 | Project storage (`packages/storage`): one implementation over directory handles for OPFS and disk folders. Autosave as in the storage POC (400 ms debounce, coalesced, atomic `createWritable`, backoff retries, conflict on outside change). An async save on unload often does not finish, so the writer also keeps unsaved edits in `localStorage` on hide and the next writer adopts them only if the disk revision and stamp are unchanged. One writer per project via Web Locks, followers via BroadcastChannel, take-over by flush then `steal`. Backups every 5 minutes, keeping the newest 20 plus one a day for 14 days. The store gained `readOnly` and `replace()`. Browser scenarios run in CI with Chrome (`pnpm test:storage`). |
| 2026-11-26 | App shell (`apps/editor`): React 19 (MIT) without a router or component library. Hash routes (`#/`, `#/project/<place>/<folder>`). Base components in `@renderly/ui/react` use the native `<dialog>` and the `popover` attribute for focus trapping, Escape and light dismiss. Deleting a project moves its folder to `.recycle/` in the same location; rename goes through a session and the rename command, and is refused while another tab edits the project. Panel sizes persist in localStorage. Dark is the default theme. |
| 2026-11-26 | Icons: Tabler Icons (outline, MIT), chosen by the owner over Lucide, a Lucide-plus-own mix and drawing our own. Only icons listed in `packages/ui/icons/icons.json` ship, named for their meaning; `build-icons.mjs` generates `src/icons.ts` and CI checks it is current. Drawn at 16px with a 2.25-unit stroke on the 24-unit grid (1.5px). `Icon` and `IconButton` (always with a tooltip) in `@renderly/ui/react`. Credited in NOTICE. Owner rule (2026-11-26): drop the word beside an icon when it would only repeat the obvious (home, undo, the theme switch); keep it for destructive and main actions, status, look-alike icons, rare actions and dialogs; icon-only controls always have a tooltip and accessible name. |
| 2026-11-26 | Media (S1.6): files are linked by handle (kept in IndexedDB per project and media id) with a fingerprint of size, modified time and the SHA-256 of the first 64 KiB; "Copy into project" streams into `media/`. Probing runs in a pool of 2-4 workers (mediabunny, headers only) and makes a 320px JPEG thumbnail in `cache/thumbs/`. Offline (missing, permission, changed, unlinked) and "cannot play" are worked out when a project opens, never stored. Relink matches by size then head, file by file or across a folder, and changes no project data, so every clip comes back. Sources may have rates sequences cannot (12, 15, 48 fps and NTSC variants; 8-192 kHz). `media.remove` refuses media in use unless `withClips`. A compound clip may now run past its sequence's end (the rest is empty). |
| 2026-11-26 | Timeline (S1.7): one canvas for the ruler and track area, redrawn once per display frame only when dirty, drawing only visible clips (binary search per track); track headers and the toolbar are React. Picture tracks show the highest index on top, audio tracks below in index order. Drags are store gestures (one undo step, Escape cancels); the store's `committed` project is what saving writes, so a preview never reaches disk. Filmstrip tiles sit on a source-time grid and show keyframes from a power-of-two slot grid (2 decode workers, 600-bitmap LRU). Mouse wheel scrolls time (Shift: tracks), a trackpad scrolls both ways, pinch or Ctrl/Alt/Cmd zooms; a notched wheel is told apart by whole-line or 120-multiple deltas. View scroll is pixels (`scroll.y`). Until S1.9: S split, Delete, Shift+Delete ripple, V/B tools, = and - zoom, Shift+Z fit, arrows step frames; Ctrl during a drag inserts. |
| 2026-11-26 | Evaluator and playback (S1.8): core `evaluateSequence` lowers a sequence to layers (visible video tracks bottom first; enabled clips at speed 1 with readable media; static transforms) and `frameAt` gives the frame graph at a time with a stable FNV-1a hash; engine `cutsFromGraph` turns it into the edit list, for the editor and the benchmark alike. The engine changes in place (`update`): sources are only appended, decoders keep their files, streams and queued frames of unchanged runs carry over; a changed run's layer holds its last frame until the new one decodes. The editor sends an update only when the graph hash (plus the files) changed, one at a time, newest wins. The render worker writes [playhead, playing, refresh count] to shared memory every refresh; the editor copies it into the view store once per display frame. Sound is layer 0 unless muted, padded with silence to the sequence's end so the clock runs while upper layers play; a sound change during playback restarts at the playhead. Pause rests on the sequence's frame grid. Loop: the selected clips' span, else the whole sequence. Viewer zoom is a GL viewport rect (fit, 25-200%, drag to pan) on the theme's `viewer` colour. Text, effects, keyframes, speed and compound clips draw nothing yet. |

Keymap: Space, J/K/L (J steps back a second: no reverse play yet), arrows for frames and cuts, Home/End, S split, D select under the playhead, Delete and Shift+Delete, , and . nudge (Shift ×10), Alt+↑/↓ move between tracks, [ and ] trim to the playhead, V/B tools, N snapping, = - Shift+Z zoom, Shift+L loop, Shift+F viewer fit, Ctrl+I import, Ctrl+Z/Ctrl+Shift+Z, ? or F1 the shortcuts list. |
| 2026-11-27 | Transform (S2.1), project schema version 2: the transform component has `position`, per-axis `scale` [x, y] with a `uniform` link flag (an inspector setting), `rotation` (degrees clockwise about the anchor), `anchor` (a fraction of the clip's fitted picture from its centre), `flipX`, `flipY`, `opacity`. The 1 → 2 upgrade turns a number scale (and its keyframes) into a pair; the v1 fixture stays as `holiday-edit.v1.project.json` and must upgrade to exactly the v2 fixture. The compositor maps each output pixel back through position, rotation (in pixels, so non-square frames do not shear), scale, anchor and mirroring. Golden frames: a CPU reference renderer (`packages/engine/src/reference.ts`, with its own unit tests) is the expected picture, and `pnpm test:golden` (in CI and verify) compares the compositor with it within 3 steps on all but 0.2% of pixels, on any GPU or none; on failure it writes the GPU, reference and difference pictures. Inspector edits use `component.setMany` (many clips, one value or one per clip, one element of a pair; creates the component with its defaults) and `component.reset`. |
| 2026-11-27 | Keyframes (S2.2): keys are { t (clip time), v, ease, in?, out? } per property (`keyframes.ts`). A key's ease shapes the span after it: hold, linear, or a cubic curve in *progress space* (time 0..1 over the span, value moving from one key to the next by the curve's progress), so numbers and pairs ease alike. Handles are [time offset in whole flicks, progress offset]; a written handle wins, otherwise "bezier" keys ease flat and "auto" keys take Catmull-Rom-like handles from their neighbours. Inserting a key splits the curve exactly (de Casteljau) after writing out the neighbours' derived handles, so the motion is unchanged; trims and splits add a key at the new start the same way. Property tests (1,500 random cases each, numbers and pairs) check inserting and shifting keep every value, and fail when the neighbour freezing is removed. A span whose curve returns to its start value cannot be split exactly (the closest is used). Commands: `keyframe.add` (fields of several clips at one timeline time; position and scale are pairs, keyed together; the section's group key keys all), `keyframe.remove` (the last key leaves the property at its value), `keyframe.move`, `keyframe.ease`; `component.setMany` with a `time` edits the key there on an animated field. The engine evaluates animated runs every refresh (`runTransformAt`); runs with keys are not merged. |

## Unproven assumptions

These come from the spec and have no proof of concept behind them yet.

- Multi-layer WebCodecs playback on an audio clock, rendered in a worker. Single-layer playback on
  the audio clock is proven (S0.4); several layers and cuts are S0.5 and S0.6.
- Streaming export to disk with flat memory (S0.8).
- A real audio engine: many tracks, effects, pitch-preserving speed, chunked offline mix (S2.4, S2.5).
- The text engine: HarfBuzz in WASM with a GPU glyph atlas (S4.1).
- The scripted-pack sandbox at 60 fps (S3.9).
- Disk-folder projects surviving a browser restart (manual check in S1.4).
- Safari and Firefox WebCodecs coverage has not been verified against current releases (R.3).
